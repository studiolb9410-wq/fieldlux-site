(00) PRIVACY

WHAT WE KEEP, AND WHERE IT LIVES.

FieldLux is two things, and they hold different data. This site is a set of static pages with no account, no cookies and no analytics. The app at app.field-lux.com is where an account and your saved work live. This page keeps them apart so you can see which is which.

Everything claimed below about this site can be checked from the outside: open the page source, or watch your browser's network panel while you read. If a clause is unclear or wrong, say so at jay@field-lux.com and it gets rewritten.

Last updated: September 6, 2026

(00) THIS SITE

THE PAGES YOU ARE READING RIGHT NOW.

Static HTML, one stylesheet, some images and self-hosted fonts, all served from this domain. There is no form on any page of this site, so there is nothing here for you to submit and nothing for us to receive.

  1. (01)

    NO COOKIES, NO ANALYTICS

    These pages set no cookies and load no analytics, tag manager or tracking script. The stylesheet, the fonts and every image come from field-lux.com itself, so reading this site sends no request to a third party. There is no visitor counter, no session recorder and no record of where you clicked.

  2. (02)

    WHAT YOUR BROWSER KEEPS

    One preference is stored on your device by these pages: fieldlux_motion, written when you press Reduce motion in the footer. Three further keys exist only so a review build can be pointed somewhere else, and are written only if you open the site with the matching query parameter: fieldlux_flow_app_url, fieldlux_discord_url and fieldlux_embed_src. Those four are everything the pages themselves write. The 3D demo on the home page is the FieldLux app served from this same domain, so the view settings it remembers, all of them named with a fieldlux_ prefix, are written into this site's local storage rather than a separate one. None of these keys is sent anywhere, none is readable by another site, and clearing site data removes all of them.

  3. (03)

    THE DEMO FRAME ON THE HOME PAGE

    The home page carries a live 3D demo of the app, and it is served from this domain. The build sits at field-lux.com/embed, it is compiled from our own repository and committed to this site, and it loads automatically when the page opens rather than waiting for a click. Because it is the same origin as this page, the frame is not a security boundary and is not offered as one: the demo can read this document and this site's local storage exactly as though the app were written into the page, which is acceptable only because it is our code on our deployment. What it cannot do is leave: the frame is sandboxed without top-level navigation and without forms, so it cannot take you anywhere and there is nothing in it to submit. It contacts no other origin. A review build can point the frame somewhere else with ?embedSrc=, and that address is accepted only when it resolves to this exact origin; anything else is refused and the stored value cleared.

  4. (04)

    LINKS THAT LEAVE THIS SITE

    Sign in and Start free go to app.field-lux.com. They carry one parameter, siteReturnUrl, holding the address of the page you left so the app can send you back to it. The Discord link opens discord.gg in a new tab. What either service records once you are there is governed by that service, not by this page.

  5. (05)

    HOSTING

    Vercel serves these files. Like any web host it records the requests it serves. We add nothing to that record and we keep no second log of our own.

(00) THE APP

WHAT AN ACCOUNT STORES.

Everything below happens at app.field-lux.com, after you create an account, and signing up writes an explicit consent record alongside it. FieldLux is in open beta and signup is public. The closed-beta waitlist it replaced still leaves records behind, which is why one of these clauses is about it.

  1. (01)

    ACCOUNT DATA

    Account login runs on Supabase Auth. Your email address is your FieldLux ID, and it is the only value that tells one account from another. You can sign in with an email code, with Google, or with a password if you choose to set one. Passwords are held on the Supabase Auth side and never reach FieldLux in a form we can read.

  2. (02)

    PROJECT DATA

    Saving a project stores its name, scene snapshots, project versions, model file references, sharing settings and the metadata needed to reopen and share the work. Ownership is tied to your Supabase user id: a saved projection study belongs to the account that created it, row-level security scopes it to that owner, uploaded files sit under a storage path of their own, and signing in with that same account is what brings the work back.

  3. (03)

    SHARE LINKS

    A share link is resolved on the server rather than handed out as the project itself. If you put a password on a link, it is stored hashed with bcrypt. Each attempt to resolve a link writes one row holding the link's id, the outcome, and a hash of the requesting network address rather than the address, which is what the rate limiting counts against. Anyone holding a live link can open what you shared, which is the whole point of a link, so the link is the credential: send it the way you would send a door code.

  4. (04)

    FOUNDING MEMBER RECORDS

    Existing approved beta testers are preserved as Founding Members. We store the approved email and, after sign-in, may link it to the matching auth user id. That link is what applies launch and billing benefits to the right account later.

  5. (05)

    WAITLIST HISTORY

    Older beta request records may remain, limited to what operational history, abuse prevention and support context need them for. Public signup no longer requires waitlist approval.

  6. (06)

    SERVICE PROVIDERS

    Supabase for authentication, database and file storage. Vercel for hosting. Resend carries the mail: the sign-in codes, the invite mail and any reply we send you all pass through it. Traffic between you and those services is carried over TLS. We do not sell personal information, and we do not build a marketing mailing list out of FieldLux account data.

  7. (07)

    MAIL YOU SEND US

    Mail to jay@field-lux.com is stored. The sender address and name, the subject, the body, any attachment and the delivery record are kept in the same database as the rest of the account data, so that a support thread can be read back later, and any reply we send is archived beside it. Only an administrator can read that mailbox. This includes the mail you would send to ask for deletion, correction or export, which is the one place on this page where writing to us and having it recorded are the same act.

  8. (08)

    PROVING THE ADDRESS IS YOURS

    Signing up and claiming founding-member standing both send a one-time code to the address you typed. The code itself is never stored in a readable form, only as a hash we can check your answer against, and it expires. Each attempt is logged with the address, the browser, and a hash of the requesting network address rather than the address itself. Those logs are pruned daily. That log is what stops one script from mailing codes at a thousand strangers.

  9. (09)

    NO PAYMENT DATA

    There is no checkout in FieldLux and no payment code in the build, so no card, no billing address and no payment processor record exists for any account. The pricing page publishes what plans would cost; nothing on it has ever charged anyone.

(00) YOUR CHOICES

ASK FROM THE ADDRESS ON THE ACCOUNT.

One route and one address. The account email is what proves the request is yours, so it is the only thing we ask you for.

  1. (01)

    DELETION, CORRECTION, EXPORT

    Email jay@field-lux.com from the address associated with your account and say which of the three you want. That address is how the request is confirmed as yours.

  2. (02)

    DELETING THE ACCOUNT

    Account deletion carries a 7-day grace period before the records go.

  3. (03)

    WHEN THIS PAGE CHANGES

    The date under the title moves when the text does. There is no mailing list to announce a change on, which is exactly why the date sits where you can see it.
